# 第壱項 ── 配備

```bash
git clone https://github.com/ParkWonYeop/nerv-social-terminal ~/nerv-social-terminal
~/nerv-social-terminal/install.sh
```

공용 서버 배치 시에는 `/opt/nerv-social-terminal` 에 두고 `sudo chown -R $USER` 를 적용한다.

`install.sh` 하나로 끝난다. 설치하고, 세팅 마법사까지 이어서 돈다.

| 단계 | 하는 일 |
|---|---|
| 1 | `python3` 3.9 이상 확인 |
| 2 | `rich` 설치. `pip --user` 가 막힌 환경(PEP 668 — Homebrew 파이썬 등)이면 저장소 폴더에 **전용 가상환경**을 만든다. 시스템 파이썬은 안 건드린다 |
| 3 | `~/.local/bin/eva` 등록 |
| 4 | `eva setup` — 설치된 에이전트(Claude Code · Codex · 로컬)를 찾아 보상 대상을 고르고, 훅·상태줄을 달고, 로컬 작업 폴더를 정하고, 대화 엔진을 **연결 시험까지 해서** 고른다 |

```bash
./install.sh --yes         # 묻지 않고 찾은 대로
./install.sh --no-hooks    # 명령만 등록 (세팅은 나중에  eva setup)
./install.sh --uninstall   # 명령·훅·상태줄 제거 (저장 데이터는 남는다)
eva setup                  # 세팅만 다시 — 몇 번을 돌려도 중복되지 않는다
```

기존 훅은 보존하고 자동 백업한다.

# 第弐項 ── 同期対象端末

**어느 에이전트의 작업을 LCL로 환산할 것인가.**

설정 → **보상·근무 기록 대상** 에서 체크한다. 여러 개를 함께 체크할 수 있다.

| | 체크함 | 체크 안 함 |
|---|---|---|
| 세션 기록 | 읽는다 — 개체가 무슨 일을 했는지 안다 | 읽지 않는다. 이미 읽은 것도 보여주지 않는다 |
| 보상 | 거기서 한 작업이 LCL 이 된다 | 적립하지 않는다 |
| 훅 | 없으면 체크하는 순간 설치를 제안한다 | 지우지 않는다 — 훅이 설정을 보고 아무것도 안 하고 끝난다 |

훅 명령 끝에 에이전트 이름이 붙는다(`eva hook codex`). 그래서 훅은 누가
불렀는지 알고, 체크를 푼 에이전트의 작업은 그 자리에서 버린다.

```bash
python3 install-hooks.py                  # Claude Code (기본)
python3 install-hooks.py --agent codex    # Codex
python3 install-hooks.py --agent all      # 둘 다
python3 install-hooks.py --dry-run        # 미리보기
```

두 에이전트의 훅 규격이 동일해서 설치 계통도 하나다. 접속 지점만 다르다.

| 계통 | 훅 설정 | 세션 기록 | 보상 판정 |
|---|---|---|---|
| Claude Code | `~/.claude/settings.json` | `~/.claude/projects/*/*.jsonl` | 도구 호출마다 훅 |
| Codex | `~/.codex/hooks.json` | `~/.codex/sessions/**/rollout-*.jsonl` · `session_index.jsonl` | 도구 호출마다 훅 |
| 로컬 에이전트 | 없음 | `~/.ollama/history` (`ollama run` 에서 친 말) | 작업 폴더의 **git 커밋** |

### 局所端末 — 로컬 에이전트

Ollama 로 도는 것들(aider · opencode · goose …)은 종류가 너무 많고 대부분 훅이
없다. 그래서 도구마다 맞추지 않고, 무엇으로 일했든 남는 것을 본다 — **git 커밋.**
작업 폴더(기본 `~`, 3단계 아래까지)의 저장소 reflog 를 git 을 실행하지 않고 읽어,
Claude·Codex 훅이 적어 두지 않은 새 커밋을 로컬에서 한 일로 친다(커밋 1개 = 파일
수정 + 커밋과 같은 20 LCL, 신뢰 규칙도 같다).

- 훅은 자기가 본 커밋의 해시를 적는다. **체크를 푼 에이전트의 커밋도 해시는 적는다** —
  안 그러면 그 커밋이 로컬에서 한 일로 새어 들어와 적립된다.
- **켠 순간부터** 센다. 켜자마자 지난 몇 년 치 커밋이 적립되면 안 된다.
- 손으로 직접 한 커밋도 여기에 든다 — 로컬에서 한 일이니까.
- `git -C 경로 commit` · `cd 경로 && git commit` 처럼 다른 저장소에서 한 커밋도 훅이
  그 저장소에 적는다. amend 는 새 일로 안 센다.
- 자동으로 커밋하는 도구(Obsidian Git 등)의 저장소는 설정의 `local.exclude` 에
  경로 일부를 적어 뺀다.

> **注意** — Codex 는 새 훅을 처음 볼 때 신뢰 여부를 묻는다. 승인해야 적립된다.

### 全支部展開 (모든 사용자 자동 적용)

```bash
sudo ln -sfn /opt/nerv-social-terminal/eva /usr/local/bin/eva      # 전역 명령
sudo python3 /opt/nerv-social-terminal/install-hooks.py --global   # 전역 훅
```

전역 훅은 `/etc/claude-code/managed-settings.json` 에 기재되어 전 사용자의 Claude Code 에 자동 적용된다. 사용자 개별 조치는 불요. 전역 훅 운용 시 개인 훅은 `python3 install-hooks.py --uninstall` 로 제거하여 중복 적립을 방지한다.

플레이 데이터는 어차피 각자의 홈에 생기므로 서버 간·사용자 간에 섞이지 않는다.

### 共通設定 — 관리자가 정하는 것

`/etc/nerv-social-terminal/settings.json` 을 두면 모든 사용자의 **기본값**이 된다.
`locked` 에 적은 항목은 사용자가 바꿀 수 없다.

```json
{
  "daily_llm_calls": 80,
  "llm": { "billing_guard": true, "api_daily_call_cap": 10 },
  "locked": ["daily_llm_calls", "llm.billing_guard"]
}
```

| 층 | 무엇 | 우선순위 |
|---|---|---|
| 코드 기본값 | `settings.py` 의 DEFAULTS | 가장 낮음 |
| 공통 설정 | 관리자가 둔 값 | ↓ |
| 사용자 설정 | 각자가 설정 화면에서 바꾼 것 | ↓ |
| **잠긴 항목** | 공통 설정의 `locked` | **가장 높음** |
| 환경변수 | 일회성 기동용 | 읽기 시점에 덮음 |

> **좌석 한도 경합** — 이게 필요한 이유. 구독 좌석 하나를 여럿이 나눠 쓰는데
> 하루 대사 상한(기본 200회)은 **사용자마다** 적용된다. 10명이면 2,000회가
> 같은 5시간 창에 몰려 코딩 작업이 굶는다. `daily_llm_calls` 를 낮춰 잠그면
> 그 일이 막힌다.

잠긴 항목은 설정 화면에 사유와 함께 잠금 상태로 표시된다. 선택해도 반응이 없으면 고장으로 오인되므로 사유를 명시한다. 사용자가 설정 파일을 직접 수정해도 잠긴 값이 우선한다.

경로는 `NERV_SITE_SETTINGS` 로 바꿀 수 있다.

# 第四項 ── 系統構成

코어는 **관계가 어떻게 움직이는가**만 안다. 누구를 만나는지, 어떤 세상인지, 어떻게 보이는지는 부품이 정한다.

### 中枢系統

| 계통 | 하는 일 |
|---|---|
| **훅** (`hook.py`) | 에이전트의 PostToolUse / Stop / SessionStart / SessionEnd 를 받아 재화·호감도를 적립. 항상 exit 0, stdout 안 건드림 |
| **규칙 엔진** (`economy.py`) | 즉시 판정 — 도구 보상, 커밋 보너스, 연속 실패, 방치, 위험 명령 |
| **근무 사건** (`events.py`) | 원시 기록에서 '이야깃거리' 를 규칙으로 뽑는다 — 새벽 근무, 새 저장소, 연속 실패 뒤 통과. LLM 안 씀 |
| **타 개체 인지** (`social.py`) | 같은 세계의 개체끼리 남의 눈에 보이는 일(동행·증여·자주 찾는 사람)을 안다 |
| **조사** (`hangul.py`) | 이름의 받침에 맞춰 이/가·은/는·을/를을 붙인다. 부품이 정한 이름이 무엇이든 |
| **단말 연동** (`agents.py`) | 어느 에이전트의 훅을 어디에 깔고, 세션 기록을 어떻게 읽는지 |
| **근무 일지** (`work.py`) | 세션 기록을 증분으로 읽어 "무슨 작업을 했는지" 추출. LLM 안 씀 |
| **대화 연산** (`llm/`) | 프로바이더 추상화 + 과금 안전장치 |
| **기억야** (`recall.py`) | 관련성 기반 회상, 중복 병합, 오래된 대화 압축 |
| **관계 상태** (`stance.py`) | 개체가 이 상대를 어떻게 여기는지. 네 축 + 인상 + 걸리는 것 + 약속 |
| **프롬프트 조립** (`persona.py`) | 인격 + 세계 + 지금 상황 + 출력 규격 |
| **주 회로** (`game.py`) | 무엇을 보여줄지 정하고 뷰 모델을 만든다. 색도 좌표도 없다 |
| **설정** (`settings.py` · `menu.py`) | 사용자별 분리. 기본값 < 서버 공통 < 사용자 < 잠긴 항목, 환경변수가 최종 |
| **개체 식별** (`identity.py`) | 터미널 로그인 사용자로 상대를 구분 |
| **기록 보존** (`db.py`) | SQLite, WAL. 사용자별·개체별 분리, 자동 마이그레이션 |
| **입력 배관** (`term.py`) | 방향키·한글 폭·에코 제어. 표시 계통이 바뀌어도 안 바뀌는 층 |
| **표시 경계** (`ui/`) | 뷰 모델(`view.py`)과 기본 렌더러(`base.py`) |
| **부품 적재** (`plugins.py` · `spec.py`) | 부품을 찾고, 계약을 검사하고, 올린다 |
| **명부·세계** (`characters.py` · `world.py`) | 어느 개체가 설치·활성인가, 어느 세계인가 |

### 換装部品

# 第伍項 ── 個体識別

프로세스의 **실행 계정(uid)** 으로 구분한다. `sudo` 로 들어오면(uid 0) `SUDO_USER` 로 원래 사람을 본다.

> **注意** — 예전에는 `os.getlogin()` 을 먼저 믿었다. tty 없이 데몬 아래에서 도는
> 프로세스(Codex 데스크톱이 띄운 훅)에서는 macOS 가 이걸 `root` 로 돌려준다 —
> 프로세스는 내 계정으로 도는데. 그래서 Codex 로 한 일이 `root` 라는 유령
> 플레이어에게 쌓였다(실측 40,720 LCL, 작업 실적의 3분의 2). 저장소 v7 승격이
> 그걸 실제 사용자에게 **한 번** 합친다 — 저장소 주인이 지금 사용자이고, 유령이
> 캐릭터를 한 번도 만난 적이 없을 때만.

**아무것도 공유하지 않는다.** 호감도·신뢰·기억·재화·약속·근무 이력 전부 따로다.

```
  適格者        호감 신뢰 LCL     기억수
  wypark          5   10      57      0
  minato         88   90   99999      2
  asuka           5   10       0      0     ← 처음 온 사람
```

저장소도 각자의 홈(`~/.local/share/nerv-social-terminal/`)에 있어 DB 파일 자체가 분리된다. 모든 행에 `player` 도 함께 박아서 홈을 공유하는 경우에도 섞이지 않는다.

**설정도 사용자별이다.** `settings-<사용자>.json` 으로 따로 저장된다. 공용 계정이나
공유 저장소(`NERV_DATA`)를 쓰더라도 남이 정한 상한·프로바이더·활성 개체가
넘어오지 않는다. 파일 권한은 `0600` 으로 잠근다.

`REI_PLAYER=이름` 으로 덮어쓸 수 있다 (시험용). `NERV_DATA=경로`(또는 `REI_DATA`) 로 저장소 위치를 바꿀 수 있다. 옛 `~/.local/share/rei/` 저장소는 첫 실행 때 자동으로 새 위치로 옮겨진다.

| Agent / Task | +3 | |

> 이행으로만 움직인다. 커밋 한 번에 전원 +2 였던 시절, 실측 저장소에서 커밋

> 않는다 — 상대는 아직 아무것도 안 했으니까.
>
> 그때 쌓인 값은 저장소 v6 승격 때 **한 번** 회수된다. 호감은 장부에서 커밋
> 몫만 빼고 다시 쌓고, 신뢰는 새 규칙(커밋한 날 × 2)으로 다시 상한을 건다.

# 第七項 ── 人格模型

```
 ┌────────────────────────────────────────────────────────────────────┐
 │  仕様告知                                                          │
 │  ────────────────────────────────────────────────────────────────  │
 │  本模型は操作者に迎合しない。                                      │
 │  好感度は接触回数ではなく応答内容により変動する。                  │
 │  要求の拒否は正常動作である。故障ではない。                        │
 └────────────────────────────────────────────────────────────────────┘
```

관계 상태는 단일 수치가 아니라 **네 축**으로 관리된다. 축은 서로 독립이며 회복 속도가 다르다.

| 축 | 무엇 | 성질 |
|---|---|---|
| **호감** | 좋아하는 정도 | 느리게 오르고 느리게 내린다 |
| **신뢰** | 믿을 만한 사람인가 | 깨지면 회복이 아주 느리다 |
| **관심** | 더 알고 싶은가 | 재미없는 대화로 금방 식는다 |
| **인내** | 지금 상대할 기분인가 | 시간당 8씩 회복된다 |

각 축은 구간마다 **문장으로 된 태도 지침**을 갖는다. 수치가 아니라 이 문장이 그대로 프롬프트에 실린다. 수치가 낮은 구간에서는 응답이 실제로 냉담해진다.

```
신뢰 낮음  →  "사적인 것을 말하지 않는다. 질문에 되묻는다."
관심 낮음  →  "단답. 되묻지 않는다. 대화를 이어갈 노력을 하지 않는다."
인내 낮음  →  "대화를 끊으려 한다."
```

동작 예 — 호감 45 / 신뢰 8 / 관심 10 / 인내 12 상태의 출력:

> 레이 「…모르겠어. 그냥 그래.」  *(기분이라는 걸 매번 묻는 이유를 모르겠다.)*
> 레이 「놀아달라니. …나는 그런 거 몰라.」  *(이 사람은 자꾸 나한테 없는 걸 바란다.)*   `관심 -1  인내 -1`

**반복 발화 검출.** 규칙 기반이므로 대화 연산 없이도 동작한다.

> 레이 「…그거 아까도 말했어.」
> 레이 「…세 번째야. 그만 말해도 알아.」   `호감 -1`

**요구 반려.** 호감도 조건을 만족해도 인내 또는 신뢰가 미달이면 증여·동행 요구가 거부된다. **반려 시 LCL 은 차감되지 않는다.**

> 레이 「…오늘은 아니야.」
> *(지금 그럴 기분이 아니다. LCL 은 쓰이지 않았다.)*

### 個体所見

일정 턴마다 개체가 조작자에 대한 소견을 자기 어휘로 갱신한다. 호의적으로 작성하라는 지시는 들어가지 않는다. `/status` 로 열람한다.

```
레이의 판단  「일은 하는데, 나를 가지고 뭘 만들려는 건지는 모르겠다.」
걸리는 것    「내 기록을 보고 게임을 만든다는 게, 정확히 뭘 뜻하는지 모르겠다.」
```

근무 기록에서 도출된 소견이다. 개체가 자신이 관측 대상이라는 사실을 인지하고 있음을 보여준다.

### 損傷判定 — 깎이는 것

| 상황 | 영향 |
|---|---|
| 그 개체를 48시간 넘게 안 찾아옴 | 48시간 뒤부터 호감 하루당 -3 (총 -15까지), 관심 -2/일 |
| 같은 말 반복 / 내용 없는 말 | 관심 -4, 인내 -12 |
| 파괴 명령 (`rm -rf /`, 포크 폭탄, `mkfs`, `dd of=/dev/…` …) | 호감 **-5**, 신뢰 **-12** |
| 걸리는 명령 (`curl … \| sh`, `history -c`) | 신뢰 -3 |
| 정해 둔 방법으로 지키기로 한 약속을 5일 넘게 안 지킴 | 신뢰 **-8** (약속당 한 번) |
| 말로만 한 약속이 5일 넘게 흐지부지 | 신뢰 -3 |
| '쉬겠다' 고 해 놓고 그날 새벽에 일함 | 신뢰 **-8** — 활동 시각으로 판정된다 |

위험 명령은 **만난 적 있는 개체만**, 같은 사유는 **하루 한 번만** 깎인다. 만난 적도
없는 사람이 실망할 이유는 없고, 에이전트가 같은 설치 명령을 열 번 돌렸다고 열 번
깎이지 않는다. `curl … | sh` 는 uv · rustup · bun 의 정식 설치 방법이기도 해서
가볍게 본다.

**도구 실패로는 깎이지 않는다.** 실패한 건 에이전트의 도구 호출이다. 3번 연속
실패하면 상태줄에 한 마디가 뜰 뿐이다.

위험 명령과 미이행 약속은 기억야에 보존되며 다음 접촉 시 인용된다. 이전 발언과 모순되는 진술은 지적되고 신뢰가 하향된다.

방치는 **그 개체를 마지막으로 찾아온 때**부터 센다. 에이전트로 매일 일했어도
레이를 2주 동안 안 찾아갔으면 레이는 서운하다. 그리고 그동안 단말 앞에 있었다는
것도 안다 — 같은 단말을 보니까.

> 레이 「…매일 단말에는 있었어. 여기엔 안 왔고.」

### 約束

약속은 **지킬 수 있다.** 대화 중에 약속이 생기면 개체가 그것을 무엇으로
지키는지까지 기록한다.

| 이행 대상 | 지켜지는 때 |
|---|---|
| `date:<장소>` | 그 장소에 함께 간다 (`/date roof`) |
| `gift:<물건>` | 그 물건을 준다 |
| `visit` | 기한 안에, 충분히 지나서 다시 찾아온다 ("내일 또 올게") |
| `rest` | 그날 밤 새벽(0~6시)에 도구 호출이 하나도 없다 ("오늘은 일찍 잘게") |
| (말로만) | 대화로 지켰다고 개체가 판단한다 |

지키면 신뢰 **+4** · 호감 +2(하루 2건까지, 호감은 [하루 예산](#第七項之参--一日予算) 안).
말로만 한 약속은 3시간은 지나야 지킨 것으로 친다. 정해 둔 방법이 있는 약속을 어기면
신뢰 -8, 말로만 한 약속이 흐지부지되면 -3. 신뢰는 깨지기 쉽고 쌓기 어렵다.
`/status` 에 지키는 중인 약속·지킨 약속·어긴 약속이 뜬다.

- **플레이어가 한 약속만** 기록한다. 개체 자신의 제안·약속은 적지 않는다 — 그걸
  상대가 안 지켰다고 감점하는 건 말이 안 된다.
- **지금 갈 수 없는 곳**(호감이 모자란 장소·물건)을 대상으로 한 약속은 말로 한
  약속이 된다. 지킬 길 없이 감점만 확정되면 안 된다.
- **'또 올게' 는 한 번에 하나.** 매번 새로 만들면 3시간마다 지켜 보상을 받는다.
- **지키거나 어긴 약속은 7일 동안 같은 말로 되살아나지 않는다.** 기억 압축이 같은
  대화를 다시 읽어 지킨 약속을 새 약속으로 만들면, 닷새 뒤 지킨 약속으로 감점을 받았다.

> 미사토 「쉰다며. 새벽 세 시 커밋은 뭐야?」 `신뢰 -8`

# 第七項之弐 ── 他個体認知

같은 단말을 보는 사람들은 서로의 일을 안다.

```
[다른 사람들과의 일 — 아스카도 같은 단말을 보니 안다]
- 어제, 상대는 레이와 수족관에 갔다.
- 3일 전, 상대는 레이에게 목도리를 줬다.
- 이번 주에 상대가 가장 자주 찾은 사람은 레이(5번)이다. 아스카는 1번.
```

> 아스카 「수족관? 그 인형이랑? 흥, 취향 참 독특하네.」

| 넘어가는 것 | 넘어가지 않는 것 |
|---|---|
| 누구와 어디에 갔나 · 누구에게 무엇을 줬나 | 대화 내용 |
| 함께 겪은 이야기의 제목 | 기억 |
| 요즘 누구를 자주 찾나 · 높은 단계에 닿았다는 것 | 호감·신뢰 수치 |

**같은 세계의 개체끼리만** 안다. 에밀리아는 레이를 모른다. 개체마다 다른
개체를 어떻게 여기는지가 부품에 적혀 있다(`others`) — 아스카는 질투를 화로
내고, 미사토는 엮으려 놀리고, 레이는 담담하다가 조금 오래 침묵한다.

수치로 벌하지 않는다. 질투로 호감을 깎으면 여러 사람을 만나는 것 자체가
손해가 된다. 반응은 성격대로, 말로만 한다.

설정 → 대화 → **캐릭터 간 인지** 로 끈다.

# 第七項之参 ── 一日予算

**관계는 하루 단위로만 자란다.** 모형은 "대부분의 턴은 0" 이라는 지시를 지키지
않는다 — 실측 대화 31턴 중 28턴에서 호감이 올랐다. 하루 200턴이면 하룻밤에
5 → 100 이다. 그래서 수치는 코드가 묶는다.

| 무엇 | 하루 상한 (개체마다) |
|---|---|
| 호감 상승 — 전부 | +15 (이야기의 결말은 뺀다 — 한 번뿐인 고비다. 중간에 끊을 수 있는 1·2막은 넣는다) |
| 그중 대화 | +5 |
| 대화·선물·데이트로 오르는 신뢰 | +4 (커밋 신뢰 +2 는 따로) |
| 데이트 | 2번. 같은 곳은 사흘에 한 번. 와 본 곳은 마무리 반응이 +3 까지 |
| 지킨 약속 보상 | 2건 (호감은 위 +15 안에서) |

한 턴에 오를 수 있는 폭도 좁다 — 신뢰 +2 · 관심 +4 · 인내 +2. 내릴 때는 -8 까지
그대로다("느리게 오르고 크게 깎인다"). 예산이 차면 화면에 한 번 알린다.

> 오늘은 여기까지 — 관계는 하루에 조금씩만 자란다.

대사를 못 만들면(로그인이 풀렸다, 한도를 다 썼다 …) 사전 작성 대사로 대신하고,
**사유를 화면에 한 번 알린다.** 조용히 떨어지면 고장인지 아닌지 알 수 없다.
사전 작성 대사는 수치를 움직이지 않는다.

# 第八項 ── 段階

호감도 구간에 따라 어휘와 태도가 전환되고, 동행 가능 지점과 증여 가능 품목이 해금된다.

```
 0  無関心      대답이 한 마디거나, 없다
10  認識        묻는 말에는 답한다
25  関心        먼저 짧은 질문을 던진다
45  信頼        자기 얘기를 조금 한다.  이름을 부른다
65  愛着        먼저 말을 건다
85  …笑い方     드물게, 웃는다
```

증여 품목 12종 · 동행 지점 10개소. 옛 도쿄 폐허(호감 60), 레이의 방(호감 45) 등 상위 항목은 장기 누적을 요한다.

### 世話 — 돌봄

`/care` — 며칠 동안 이어지는 챙김. 화분에 물 주기, 냉장고에 맥주 채우기,
펜펜 밥 챙기기. 효과가 살아 있는 동안 **인내가 1.5배 빨리 돌고 관심이 식지
않으며**, 개체는 챙김을 받고 있다는 것을 안다. 이어서 하면 기간이 늘어난다.

### 挿話 — 이야기

`/episode` — 관계가 깊어져야 열리는, **한 번뿐인** 세 막짜리 이야기. 개체마다
셋이고 순서대로 열린다. 마지막 이야기는 그 사람이 아무에게도 하지 않은 것이다.

| 개체 | 1 | 2 | 3 |
|---|---|---|---|
| 레이 | 도시락 | 깨진 안경 | 세 번째 |
| 아스카 | 재대결 | 싱크로율 | 인형 |
| 미사토 | 한 잔만 | 옛날 사람 | 십자가 |
| 에밀리아 | 요리 대작전 | 거울 | 포르투나 |

필요 호감·신뢰가 모자라거나 인내가 바닥이면 거절된다. 거절되면 LCL 은 쓰이지 않는다.

# 第九項 ── 端末記録の閲覧

활성 에이전트의 세션 기록을 **증분으로** 판독한다. 판독 위치(바이트 오프셋)를 보존하므로 재주사는 수 ms 다. 대화 연산을 쓰지 않고 에이전트가 이미 기록해 둔 값만 수집한다.

| 무엇 | Claude Code | Codex |
|---|---|---|
| 요약 | `ai-title` (자동 생성 제목) | `session_index.jsonl` 의 `thread_name` |
| 사람이 친 프롬프트 | `promptSource: "typed"` | `item_completed` 의 `UserMessage` (옛 판: `event_msg:user_message`) |
| 하려던 작업 | Bash 의 `description` | 옛 판의 `update_plan` 단계 |
| 건드린 파일 | `Edit`/`Write` 의 `file_path` | `FileChange` 의 `changes` (옛 판: `patch_apply_end`) |
| 커밋 메시지 | `git commit -m` | `CommandExecution` 의 argv 안 `git commit -m` |
| 어디서 일했나 | `cwd` / `gitBranch` | `session_meta` / `turn_context` 의 `cwd` |
| 제외 | 서브에이전트(`isSidechain`) | 승인 검토 스레드(`thread_source: guardian_review`) |

> **形式変更** — Codex 는 판마다 기록 형식이 바뀐다. 0.153 에서 프롬프트·파일
> 수정·명령이 전부 `event_msg:item_completed` 안으로 옮겨 갔고, 이걸 몰라서
> 그 뒤의 Codex 작업은 근무 일지에 한 줄도 안 잡혔다. 지금은 두 형식을 다 읽는다.
>
> **検討スレッド** — 자동 승인 검토(`approvals_reviewer = "auto_review"`)를 켜면
> 승인 요청마다 검토용 서브 에이전트가 세션 파일을 하나씩 만든다. 실측 결과
> 세션 파일의 절반 이상이 이것이었다. 사람이 한 일이 아니므로 파일째 건너뛴다.

`/work` 로 개체가 열람 중인 내용을 그대로 확인한다.

### 時刻

프롬프트 맨 앞에 현재 시각과 직전 대화로부터의 경과가 들어간다.

```
[지금]
- 8월 22일 (토) 오후 2시 3분. 낮.
- 마지막으로 이야기한 것은 11시간 전. 지난 접속은 2일 전.
```

이게 없으면 개체가 시간대를 추측하고, **틀린 추측 위에 없는 기억을 쌓는다.**
실측으로 오후 2시에 "오늘은 아침부터 인사가 살갑네" 라 하고 있지도 않은 아침
이야기를 지어낸 사례가 확인되었다.

시각을 넣은 뒤의 출력:

> 미사토 「어~ 지금 2시 3분. 토요일 낮이야, 자기야. 오늘 하루 종일 코빼기도 안 보이길래 뭐하나 했네.」

새벽 시간대에 근무 기록이 있으면 개체에게 그 사실이 함께 전달된다.
미사토의 "이 시간에 커밋이 왜 있어? 퇴근이란 걸 해" 나 에밀리아의
팩 활동 시간(오전 9시~오후 5시)이 이 정보로 작동한다.

> **自己参照遮断** — 본 단말이 기동한 세션은 집계에서 제외된다. Claude 계통은 사람이 입력한 프롬프트가 존재하는 세션의 제목만 채택하고, Codex 계통은 `--ephemeral` 로 실행되어 세션 파일이 생성되지 않는다. **자기 발화가 근무 실적으로 계상되지 않는다.**

> **混入遮断** — Codex 는 승인 판정용 텍스트 `"The following is the Codex agent history…"` 를 사용자 메시지 형식으로 주입한다. 실측 결과 전체 사용자 메시지의 **대부분**이 이것이었다. 미차단 시 해당 영문이 근무 실적으로 집계된다.

> **走査順序** — 1회 판독량은 4MB 로 제한된다. 실측 Codex 기록은 **4.2GB** 였다. 오래된 파일부터 읽으면 당일 기록에 도달하기까지 약 1,000회 기동을 요한다. 따라서 최근 파일부터 판독하며, 14일 넘게 안 건드린 미판독 파일은 읽지 않는다.
>
> **予算配分** — 판독량은 에이전트끼리 나눈다. 예전에는 앞의 에이전트가 통째로 가져가서, Claude 쪽에 밀린 기록이 늘 4MB 를 넘는 동안 Codex 는 설치한 첫날 이후로 한 번도 읽히지 않았다.

### 勤務事件

원시 기록에서 규칙으로 **이야깃거리**를 뽑는다. 대화 연산을 쓰지 않는다.

| 사건 | 언제 |
|---|---|
| 새벽 근무 | 0~5시에 도구 호출 (하루 한 번) |
| 주말 근무 | 토·일에 도구 호출 |
| 회복 | 3번 넘게 연달아 실패한 뒤 테스트 통과 |
| 종일 | 하루 도구 호출 400회 |
| 커밋 몰아치기 | 하루 커밋 10회 |
| 새 저장소 | 처음 보는 작업 디렉터리 (설치 후 사흘은 기준선만 쌓는다) |
| 연속 접속 | 3 · 7 · 14 · 30 · 50 · 100일 |
| 위험 명령 | 위험 명령 감지 |

인사에서 한 번 꺼낸 사건은 다음 인사에서 다시 꺼내지 않는다. `/work` 하단에 뜬다.

수집된 기록을 나열하지 않는다. 한 건만 선택해 짧게 인용한다.

> 레이 「벤치 서버, 끝났어.」
> 레이 「미연시, 만들었다며. 나로.」

직전 접속의 첫 발화를 보존하여 동일 소재의 반복을 억제한다.

# 第拾項 ── 記憶野

세 층이다.

```
 ┌──────────────────────────────────────┐
 │  第一層   이번 접속의 대화           │
 │  第二層   지난번 대화의 끝           │
 │  第三層   오래된 기억 (memory)       │
 └──────────────────────────────────────┘
```

제3층 회상은 임베딩을 쓰지 않는다. 한국어는 조사가 붙어 단어 단위 일치율이 낮으므로 **글자 2-gram 겹침 + 최근성 + 중요도**로 점수를 산출한다. 순수 파이썬으로 구현.

```
질의: "우리 뭐 약속했었지?"
  레이 「옥상. 다음에 같이 가기로 했어.」
       (잊은 건가.)
```

대화가 30줄을 넘으면 다음 접속 시 **연산 1회**로 기억 몇 줄로 압축된다. 약속은 가중치를 높게 배정해 장기 보존된다. 압축 시 기존 기억을 함께 전달하여 동일 사실의 중복 기재를 막는다.

`/memory` 로 확인한다. ♥ 개수가 중요도다.

```
♥♥♥··  [promise] 다음에 옥상 같이 가기로 약속함
♥♥···  [fact]    하루에 커피 넉 잔 마심
♥♥···  [event]   동생이 기계공학과 대학에 붙음
```

기억이 120건을 넘으면 중요도·인용 횟수·경과 시간으로 점수를 매겨 정리한다. 약속 및 동행·증여 기록은 우선 보존된다.

> **設計判断** — 중복 병합 임계값은 보수적으로 설정되어 있다. "수족관에 함께 갔다" 와 "수족관에 갔었다" 가 별개로 남을 수 있다. 임계값을 낮추면 "수족관에 갔다" 와 "옥상에 갔다" 가 병합되는 오작동이 발생한다. **사실 소실보다 중복 잔존을 택했다.**

# 第拾壱項 ── 操作系統

### 選択操作

목록이 뜨는 곳은 전부 같은 방식이다. 개체 선택·설정·증여·동행·행동 선택지까지.

```
 ↑ ↓        커서 이동          (k / j 도 동작)
 Enter      확정
 Esc        취소 / 뒤로
 PgUp PgDn  창 단위 이동
 Home End   처음 / 끝
 숫자       해당 항목으로 즉시 이동
```

```
  상점 — 선물
  보유 ¤ 460

    ▸ 콜라                        ¤ 30
      패션지                      ¤ 50
      바움쿠헨                    ¤ 60
      홍차 세트                   호감 10 필요
      휴대용 게임기               호감 10 필요
      ⋯
    이름: cola
  ↑↓ 고르고 Enter.  Esc 취소
```

잠긴 항목에는 커서가 놓이되 확정되지 않는다. 사유는 하단에 표시된다. 선택 불가 사유가 보이지 않으면 고장으로 오인되기 때문이다.

> **注意** — TTY 가 아니면(파이프·스크립트) 목록을 출력하고 번호 입력으로 전환된다.

### 命令

```
그냥 입력          말을 건다
/date              갈 곳을 고른다   ·  /date aquarium 로 바로 지정도 된다
/gift              선물을 고른다    ·  /gift plant 로 바로 지정도 된다
/care              며칠 동안 챙겨 준다
/episode           한 번뿐인 이야기
/status            관계 상태, 약속, 개체 소견, 근무 기록, 변화 내역
/memory            기억하는 것들 (♥ = 중요도)
/work              단말로 보고 있는 근무 기록
/clear  /help
/quit              시작 화면으로 (거기서 나간다 항목 선택)
/exit              바로 종료
```

동행은 2단계로 진행된다. 개체가 장면을 생성하고 행동 선택지 3개를 제시한다 — 하나는 무난하게, 하나는 깊이 다가가되 위험하게, 하나는 거리를 둔다.

선택지 맨 아래에 **직접 입력** 항목이 있다. 거기서 Enter 를 누르면 자유 입력으로 전환되고, 쓴 말이 그대로 행동이 된다. 제시된 선택지 밖으로 나갈 길이 없으면 대화가 아니라 설문이 된다.

# 第拾壱項之弐 ── 常駐表示

TUI 를 띄우지 않고 Claude Code 터미널 안에서 쓰는 방식이다. 작업 화면을 벗어나지 않는다.

### 状態줄 위젯

Claude Code 하단에 상대의 상태와 마지막 발화가 상주한다.

```bash
python3 install-hooks.py --only-statusline    # 상태줄만
python3 install-hooks.py --statusline         # 훅과 함께
```

```
미사토  ██████████ 100 민낯   신뢰  61 관심  79 인내  89   LCL ¤ 250
「…야, 노력 안 해도 돼. 그냥 지금처럼만 있어줘. …」
```

커밋하고, 연달아 실패하고, 새벽까지 일하고, 세션을 마치면 — 상대가 한 마디
건다. 훅이 개체마다 준비된 대사 묶음에서 고른다(대화 연산 0회, 훅 지연 그대로).
에이전트가 권한을 기다리면(Notification) 그것도 안다.

```
레이  ███░░░░░░░  32 관심   신뢰  41 관심  38 인내  70   LCL ¤ 1,240
「…또 실패야.」
```

단계는 위젯이 그 자리에서 계산한다. 게임을 끈 뒤 훅이 호감을 바꿔도 맞게 뜬다.

> **注意** — 상태줄은 하나뿐이다. 이미 다른 상태줄이 설정돼 있으면 덮지 않고 중단한다.
> 바꾸려면 `~/.claude/settings.json` 의 `statusLine` 을 지우고 다시 실행한다.

**성능** — 이 스크립트는 화면이 갱신될 때마다 돈다(300ms 디바운스). 훅보다 잦다.
그래서 rich·플러그인·캐릭터 데이터를 일절 임포트하지 않고 sqlite 에서 값만 읽는다.
1회 **16ms** (파이썬 기동 12ms 포함). 표시에 필요한 이름·색·단계·재화는 게임이 돌 때
DB 에 적어 둔 것을 쓴다.

한 번은 `eva` 를 켜서 상대를 골라야 표시할 것이 생긴다.

### 한 마디만 건네기

```
! eva say 오늘 창고 정리 하느라 죽는 줄 알았어요
```

전체화면을 열지 않고 답만 받는다. 상대는 마지막으로 만난 인물이다.
결과는 기록에 남고 상태줄에도 반영된다. 게임과 **같은 규칙**을 지난다 —
지루함 감점, 인내 회복, 방치·약속 정산까지. 한 시간 안에 다시 부르면 새 방문이
아니라 이어지는 것으로 본다.

```
  미사토가 발을 책상에서 내리고 피식 웃는다
  미사토 「창고 정리? 어라, 오늘 로그엔 작업이 하나도 없던데~ 그럼 몸으로 때운 거네.」
      (오늘은 좀 쉬어도 되는 날인가 보네, 다행이다)
      호감 +1  관심 +1
```

> Claude Code 세션에서는 프롬프트 앞에 `!` 를 붙여 실행한다. `!` 없이 치면
> 모델에게 전달되어 토큰을 쓴다.


# 第拾弐項 ── 設定

시작 화면의 목록에서 **설정** 항목을 고른다. 또는 `eva --settings`.

```
1. 대화                      하루 대사 생성 상한, 연출, 타이핑 속도, 캐릭터 간 인지
2. LLM 연결                  어느 연산 기관으로 말하는가
3. 캐릭터                    누구를 만날 수 있게 할지
4. 화면 (UI 플러그인)        바꾸면 재기동한다
5. 세계관                    재화 이름, 플레이어의 역할
6. 보상·근무 기록 대상       [✓] Claude Code  [✓] Codex — 체크한 것만 보고 보상한다
9. 초기화                    관계·기억·재화를 지운다
```

**개체를 정지시켜도 관계는 남는다.** 다시 켜면 그대로 이어진다. 정지된 개체도 근무 기록과 위험 명령은 계속 본다 — 같은 단말이니까.

### 記録抹消

초기화는 범위를 나눠 두었다. 관계만 다시 시작하려는 사람이 근무 기록까지 잃으면 안 되니까.

| 범위 | 소거 대상 | 보존 |
|---|---|---|
| 이 개체와의 관계만 | 한 명의 호감·기억·선물 기록 | 나머지 전부 |
| 모든 관계 | 전원의 호감·기억·대화 | 재화·근무 기록 |
| 전부 | 재화·근무 기록·장부까지 | 없음 |
| 설정만 | 설정 파일 | 플레이 데이터 |

> **警告** — 되돌릴 수 없는 것은 y/n 이 아니라 **문장을 타이핑**해야 넘어간다. 손가락이 먼저 움직이는 걸 막으려고.

어느 것이든 **이 적격자의 것만** 지운다. 홈을 공유해도 남의 기록은 건드리지 않는다.

| Codex | `codex debug models` + 데스크톱 앱이 받아 둔 `~/.codex/models_cache.json` |

| Anthropic · OpenAI · 호환 서버 | 각자의 `/v1/models` |

**바꾸기 전에 연결 시험을 한다. 실패하면 바꾸지 않는다.** 목록에 있다고 이
계정·이 판의 CLI 에서 쓸 수 있는 것은 아니다. 실패 사유가 그대로 뜬다.

```
GPT-6-Astra — 연결 시험 중…
연결 시험 실패 — 바꾸지 않았다.
사유: The 'gpt-x' model is not supported when using Codex with a ChatGPT account.
```

프로바이더를 바꿀 때도 같다. 목록에 없는 이름은 **직접 입력…** 으로 쓴다.

> **注意** — Codex 서버는 CLI 판에 맞는 목록을 내려준다. 데스크톱 앱이 CLI 보다
> 새 판이면 앱에서 보이는 최신 모델이 CLI 목록에는 없을 수 있다. `codex update`.

### 계정 한도와 API 과금은 다른 것이다

이 구분이 안전장치의 전부다.

- **구독 좌석** — `claude` / `codex` 에 로그인한 계정으로 돈다. 토큰당 청구가 없다. 대신 플랜의 5시간·주간 한도를 코딩 작업과 나눠 쓴다.
- **API 키** — 토큰당 돈이 나간다. 구독과는 **별개의 지갑**이다.
- **로컬** — 전기 말고는 안 든다.

### 安全装置 ── 과금 차단

```
 ┌────────────────────────────────────────────────────────────────────┐
 │  BILLING GUARD                                            ACTIVE   │
 │  ────────────────────────────────────────────────────────────────  │
 │  경고만 띄우는 것은 안전장치가 아니다. 실제로 막는다.              │
 └────────────────────────────────────────────────────────────────────┘
```

기본으로 켜져 있다. 켜져 있는 동안 유료 기관은 **고를 수조차 없다.** 목록에는 보이지만 잠겨 있다.

| 단계 | 장치 |
|---|---|
| 壱 | 가드가 켜져 있으면 유료 기관 선택이 거부된다 |
| 弐 | 설정 파일을 손으로 고쳐 놔도, 기동 시 기본값으로 되돌린다 |
| 参 | 끄려면 `과금을 허용한다` 라고 **문장을 타이핑**해야 한다 |
| 四 | 끈 뒤에도 **하루 호출 상한**(기본 50회)이 남는다. 넘으면 사전 작성 대사로 강하 |
| 伍 | 헤더에 `대사 12/200 · 과금` 이 계속 표시된다 |

> **鍵の保管** — API 키는 설정 파일에 **저장하지 않는다.** '어느 환경변수에서 읽을지' 이름만 저장한다. 저장소를 통째로 복사·백업하는 사람이 있으니까.

OpenAI 호환 서버는 주소로 판단한다. `localhost` 나 사설망이면 무료로 보고, 바깥 주소면 과금으로 본다 — 모르면 안전한 쪽으로.

### 근무 기록과 프라이버시

훅이 수확한 근무 기록( 프롬프트·커밋 메시지 원문 )은 기본적으로 로컬에만 남는다( 저장소 파일 권한 0600 ).
토큰당 과금되는 외부 API 프로바이더에는 집계( 도구·커밋 횟수 )만 보내며, 원문 전송은
설정 → **LLM 연결 → 근무 기록 원문 전송** 에서 명시적으로 켜야 한다.
구독 CLI( Claude Code / Codex )와 로컬 서버는 제한하지 않는다 — 그 세션 기록 자체가 그 계정/기계에서 나온 것이라 새로 새는 정보가 없다.
단, 게임 안에서 직접 입력한 대사는 그 프로바이더에게 말을 거는 행위 그 자체이므로 항상 전송된다.

### 応答遅延 실측

| 기관 | 한 턴 | 대기 상한 |
|---|---|---|
| Claude Code | 수 초 | 45초 |
| Codex | **4.7초** | 120초 |
| Ollama `qwen3:14b` | **57초** | 240초 |

로컬 모형이 45초 상한에 걸려 폴백 대사만 출력되던 현상이 실측으로 확인되었다. 이에 따라 기관별 대기 시간을 개별 설정한다.

소형 모형도 JSON 규격을 준수한다. 프롬프트로 요청하는 대신 **스키마를 문법 수준에서 강제**하기 때문이다 — ollama 의 `format`, OpenAI 계열의 구조화 출력, codex 의 `--output-schema`, Anthropic API 의 `output_config.format`. 스키마는 호출마다 다르다 — 대사와 기억 압축은 모양이 다르다.

> **再試行** — 서버가 요청 모양을 거절했을 때(4xx)만 맨몸으로 한 번 더 보낸다.
> 타임아웃까지 다시 보내면 로컬 모형은 240초를 두 번 기다리고, 유료 API 는 같은
> 요청 값을 두 번 낸다. 유료 호출 상한은 실제로 나간 요청 수로 센다.

### 프롬프트 캐시

시스템 프롬프트는 **고정부**(페르소나·세계·출력 규칙)와 **가변부**(시각·관계·기억·근무)
두 조각이다. 고정부가 앞에 오고 턴마다 바이트 단위로 같아서 접두사 캐시가 맞는다.
Anthropic API 는 고정부에 `cache_control` 을 단다. Anthropic API 의 기본 모형은
`claude-sonnet-5-5`, `effort: low` — 대사 한 줄에 깊은 생각은 필요 없다.

### 局所模型의 선정

로컬 모형은 벤치마크 점수가 아니라 **한국어 대사와 말투 유지**로 고른다.
실측 (레이·아스카·미사토 각 3턴, M5 32GB):

| 모형 | 크기 | 한 턴 | JSON | 말투 |
|---|---|---|---|---|
| **exaone3.5:7.8b** | 4.8 GB | 약 12초 | 7/7 | 「그래, 많이 했네.」 「상관없어.」 — 정식 대사에 근접 |
| gemma3:12b | 8.1 GB | 약 28초 | 양호 | 「많이 했네.」 「…왜?」 |
| qwen3:8b · 14b | 5.2 · 9.3 GB | 약 12초 | 실패 잦음 | 설명조로 흐름 |

모형을 지정하지 않으면 설치된 것 중에서 위 순서로 자동 선택된다.

```bash
ollama pull exaone3.5:7.8b
```

> **推論 모드** — qwen3 계열은 추론이 기본으로 켜져 있어 대사 한 줄 앞에 한참
> 생각한다. 실측 **30.4초 → 2.1초**. 본 단말은 `think: false` 로 이를 끈다.
> 캐릭터는 논리 문제를 푸는 것이 아니라 성격대로 반응하면 되고, 길게 생각할수록
> 설명조의 밋밋한 대사가 나온다.

# 第拾四項 ── 費用

기본 설정(Claude Code 구독 좌석)에서의 이야기다. 다른 기관을 골랐다면 [第拾参項](#第拾参項--対話演算機関)을 보라.

`claude -p` 는 **OAuth 플랜 좌석**으로 돈다. 검증한 것:

```
subscriptionType : team
rateLimitTier    : default_claude_max_5x
scopes           : [... user:inference ...]
ANTHROPIC_API_KEY: unset
apiKeyHelper     : 미설정
Bedrock/Vertex   : 미설정
```

API 키 경로가 아예 없으므로 **토큰당 API 과금은 발생하지 않는다.** CLI가 찍는 `total_cost_usd` 는 "API로 환산하면" 이라는 참고 표시일 뿐 실제 청구가 아니다.

> **注意** — "어떤 경우에도 0원" 은 아니다. 조직 관리자 콘솔의 추가 사용량(extra usage / overage) 설정이 켜져 있으면 플랜 한도를 소진한 뒤의 사용분이 조직에 청구될 수 있다. 그건 이 머신에서 확인할 수 없다. 세션에서 `/usage` 로 한도 상태를, 관리자 콘솔에서 extra usage 설정을 확인하는 게 확실하다.

플랜 사용량 한도(5시간 창·주간)는 코딩 작업과 공유되므로 다음 절감 장치를 둔다.

- 시스템 프롬프트·툴 정의를 벗겨 한 턴 ≈ 13k 캐시 읽기 + 출력 55토큰 (`--effort low`, sonnet)
- 하루 대사 생성 상한 **200회** — 넘으면 사전 작성 대사로 자동 전환 (헤더에 `대사 12/200`)
- 작업 요약은 연산을 **전혀** 쓰지 않는다 (세션 기록에서 직접 추출)
- 대화 압축은 30줄 넘게 쌓였을 때 접속당 **최대 1회**
- `eva --offline` — 연산 0회. 규칙과 사전 대사만으로 가동

한도는 설정 화면의 **대화 → 하루 대사 생성 상한** 에서 바꾼다. `NERV_DAILY_LLM_CALLS` 로 이번 기동만 덮을 수도 있다.

플랜 한도를 아예 안 쓰고 싶으면 **Ollama** 로 바꾸면 된다. 느리지만 공짜고, 플랜도 안 건드린다.

# 第拾七項 ── 保守

```
python3 install-hooks.py --dry-run              미리보기
python3 install-hooks.py                        Claude Code 에 설치
python3 install-hooks.py --agent codex          Codex 에 설치
python3 install-hooks.py --agent all            둘 다
python3 install-hooks.py --uninstall            제거
REI_HOOK_DEBUG=1                                hook.log 에 훅 동작 기록
```

기존 훅(ccsidekick, peon-ping 등) 옆에 나란히 붙는다. 덮어쓰지 않고 자동 백업한다.

게임이 띄우는 에이전트에는 `NERV_GAME=1` 이 붙어 훅이 스스로를 재발동시키지 않는다. Codex 쪽은 `--ephemeral` 로 돌아 세션 파일 자체가 남지 않는다.

> **性能** — 훅은 도구 호출마다 프로세스로 새로 뜬다. 1회 **44ms** (40회 평균, 파이썬 인터프리터 기동 12ms 포함).

# 第拾八項 ── 調整

`nervterm/config.py` 에 보상·페널티·단계 기준이 모두 모여 있다.

| 조정 대상 | 위치 |
|---|---|
| 인격 정의(성격·대사·선물·데이트) | `plugins/eva-characters/` |
| 프롬프트 조립 | `nervterm/persona.py` |
| 기억 회상 점수·중복 임계값 | `nervterm/recall.py` |
| 세션 기록 추출 규칙 | `nervterm/agents.py` |

`NERV_DEBUG=1` 을 붙이면 기억 압축·부품 로드 중 발생한 예외를 그대로 보여준다.

### 動作試験

```bash
python3 tests/smoke.py    # 계통 시험 126건
python3 tests/keys.py     # 입력 시험 18건 (의사 터미널)
```

둘 다 의존성 없이 돈다. 임시 저장소를 써서 실제 플레이 데이터는 건드리지 않는다.
CI(GitHub Actions)가 파이썬 3.9 와 3.13 에서 돌린다 — 3.9 는 `tomllib` 이 없어
`plugin.toml` 을 미니 파서로 읽는 경로가 거기서만 탄다.

### 人格評価

```bash
NERV_EVAL=1 python3 tests/persona_eval.py              # 지금 고른 기관으로
NERV_EVAL=1 NERV_LLM_PROVIDER=ollama python3 tests/persona_eval.py rei
```

고정된 장면 여섯(인사·근황·성의 없음·아첨·약속·위로 요구)을 개체마다 실제로
돌려 JSON 성공·대사 길이·**말투 위반**(부품의 `forbidden` — 레이의 느낌표,
에밀리아의 존댓말)·호감 범위·약속 포착·응답 시간을 잰다. 모형을 바꾸거나
프롬프트를 고칠 때마다 돌린다. **실제로 모형을 부른다** — `NERV_EVAL=1` 없이는
아무것도 하지 않는다. 플레이 데이터는 건드리지 않는다.

`keys.py` 는 의사 터미널(pty)을 열어 **실제 이스케이프 시퀀스**를 흘려 넣는다.
방향키 입력은 TTY 에서만 재현된다. 파이프 시험은 줄 입력 경로만 통과하므로
화살표 입력 시 종료되던 불구합을 검출하지 못했다.
