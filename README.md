# 第壱項 ── 配備

git clone https://github.com/ParkWonYeop/nerv-social-terminal ~/nerv-social-terminal
~/nerv-social-terminal/install.sh
```

공용 서버 배치 시에는 `/opt/nerv-social-terminal` 에 두고 `sudo chown -R $USER` 를 적용한다.

```bash
./install.sh --no-hooks    # 명령만 등록

```

소요 부품은 `python3` 와 `rich` 뿐이다 (`apt install python3-rich` 또는 `pip install rich`).

# 第弐項 ── 同期対象端末

**어느 에이전트의 작업을 LCL로 환산할 것인가.**

```bash
python3 install-hooks.py                  # Claude Code (기본)
python3 install-hooks.py --agent codex    # Codex
python3 install-hooks.py --agent all      # 둘 다
python3 install-hooks.py --dry-run        # 미리보기
```

두 에이전트의 훅 규격이 동일해서 설치 계통도 하나다. 접속 지점만 다르다.

| 계통 | 훅 설정 | 세션 기록 |
|---|---|---|
| Claude Code | `~/.claude/settings.json` | `~/.claude/projects/*/*.jsonl` |
| Codex | `~/.codex/hooks.json` | `~/.codex/sessions/**/rollout-*.jsonl` |

> **注意** — Codex 는 새 훅을 처음 볼 때 신뢰 여부를 묻는다. 승인해야 적립된다.

### 全支部展開 (모든 사용자 자동 적용)

```bash
sudo ln -sfn /opt/nerv-social-terminal/eva /usr/local/bin/eva      # 전역 명령
sudo python3 /opt/nerv-social-terminal/install-hooks.py --global   # 전역 훅
```

전역 훅은 `/etc/claude-code/managed-settings.json` 에 기재되어 전 사용자의 Claude Code 에 자동 적용된다. 사용자 개별 조치는 불요. 전역 훅 운용 시 개인 훅은 `python3 install-hooks.py --uninstall` 로 제거하여 중복 적립을 방지한다.

플레이 데이터는 어차피 각자의 홈에 생기므로 서버 간·사용자 간에 섞이지 않는다.

### 共通設定 — 관리자가 정하는 것

`/etc/nerv-social-terminal/settings.json` 을 두면 모든 사용자의 **기본값**이 된다.
`locked` 에 적은 항목은 사용자가 바꿀 수 없다.

```json
{
  "daily_llm_calls": 80,
  "llm": { "billing_guard": true, "api_daily_call_cap": 10 },
  "locked": ["daily_llm_calls", "llm.billing_guard"]
}
```

| 층 | 무엇 | 우선순위 |
|---|---|---|
| 코드 기본값 | `settings.py` 의 DEFAULTS | 가장 낮음 |
| 공통 설정 | 관리자가 둔 값 | ↓ |
| 사용자 설정 | 각자가 설정 화면에서 바꾼 것 | ↓ |
| **잠긴 항목** | 공통 설정의 `locked` | **가장 높음** |
| 환경변수 | 일회성 기동용 | 읽기 시점에 덮음 |

> **좌석 한도 경합** — 이게 필요한 이유. 구독 좌석 하나를 여럿이 나눠 쓰는데
> 하루 대사 상한(기본 200회)은 **사용자마다** 적용된다. 10명이면 2,000회가
> 같은 5시간 창에 몰려 코딩 작업이 굶는다. `daily_llm_calls` 를 낮춰 잠그면
> 그 일이 막힌다.

잠긴 항목은 설정 화면에 사유와 함께 잠금 상태로 표시된다. 선택해도 반응이 없으면 고장으로 오인되므로 사유를 명시한다. 사용자가 설정 파일을 직접 수정해도 잠긴 값이 우선한다.

경로는 `NERV_SITE_SETTINGS` 로 바꿀 수 있다.

# 第四項 ── 系統構成

코어는 **관계가 어떻게 움직이는가**만 안다. 누구를 만나는지, 어떤 세상인지, 어떻게 보이는지는 부품이 정한다.

### 中枢系統

| 계통 | 하는 일 |
|---|---|
| **훅** (`hook.py`) | 에이전트의 PostToolUse / Stop / SessionStart / SessionEnd 를 받아 재화·호감도를 적립. 항상 exit 0, stdout 안 건드림 |
| **규칙 엔진** (`economy.py`) | 즉시 판정 — 도구 보상, 커밋 보너스, 연속 실패, 방치, 위험 명령 |
| **단말 연동** (`agents.py`) | 어느 에이전트의 훅을 어디에 깔고, 세션 기록을 어떻게 읽는지 |
| **근무 일지** (`work.py`) | 세션 기록을 증분으로 읽어 "무슨 작업을 했는지" 추출. LLM 안 씀 |
| **대화 연산** (`llm/`) | 프로바이더 추상화 + 과금 안전장치 |
| **기억야** (`recall.py`) | 관련성 기반 회상, 중복 병합, 오래된 대화 압축 |
| **관계 상태** (`stance.py`) | 개체가 이 상대를 어떻게 여기는지. 네 축 + 인상 + 걸리는 것 |
| **프롬프트 조립** (`persona.py`) | 인격 + 세계 + 지금 상황 + 출력 규격 |
| **주 회로** (`game.py`) | 무엇을 보여줄지 정하고 뷰 모델을 만든다. 색도 좌표도 없다 |
| **설정** (`settings.py` · `menu.py`) | 사용자별 분리. 기본값 < 서버 공통 < 사용자 < 잠긴 항목, 환경변수가 최종 |
| **개체 식별** (`identity.py`) | 터미널 로그인 사용자로 상대를 구분 |
| **기록 보존** (`db.py`) | SQLite, WAL. 사용자별·개체별 분리, 자동 마이그레이션 |
| **입력 배관** (`term.py`) | 방향키·한글 폭·에코 제어. 표시 계통이 바뀌어도 안 바뀌는 층 |
| **표시 경계** (`ui/`) | 뷰 모델(`view.py`)과 기본 렌더러(`base.py`) |
| **부품 적재** (`plugins.py` · `spec.py`) | 부품을 찾고, 계약을 검사하고, 올린다 |
| **명부·세계** (`characters.py` · `world.py`) | 어느 개체가 설치·활성인가, 어느 세계인가 |

### 換装部品

| **인격 모형** | 페르소나·단계·선물·데이트 | 여러 개 |

동봉된 부품:

# 第伍項 ── 個体識別

터미널 세션의 **로그인 사용자**로 구분한다. `os.getlogin()` 이 제어 tty 의 로그인 사용자를 주므로 `sudo` 로 들어와도 원래 사람이 나온다. tty 가 없으면(훅 등) `SUDO_USER` → `LOGNAME`/`USER` → uid 순으로 내려간다.

**아무것도 공유하지 않는다.** 호감도·신뢰·기억·재화·약속·근무 이력 전부 따로다.

```
  適格者        호감 신뢰 LCL     기억수
  wypark          5   10      57      0
  minato         88   90   99999      2
  asuka           5   10       0      0     ← 처음 온 사람
```

저장소도 각자의 홈(`~/.local/share/nerv-social-terminal/`)에 있어 DB 파일 자체가 분리된다. 모든 행에 `player` 도 함께 박아서 홈을 공유하는 경우에도 섞이지 않는다.

**설정도 사용자별이다.** `settings-<사용자>.json` 으로 따로 저장된다. 공용 계정이나
공유 저장소(`NERV_DATA`)를 쓰더라도 남이 정한 상한·프로바이더·활성 개체가
넘어오지 않는다. 파일 권한은 `0600` 으로 잠근다.

`REI_PLAYER=이름` 으로 덮어쓸 수 있다 (시험용). `NERV_DATA=경로`(또는 `REI_DATA`) 로 저장소 위치를 바꿀 수 있다. 옛 `~/.local/share/rei/` 저장소는 첫 실행 때 자동으로 새 위치로 옮겨진다.

# 第七項 ── 人格模型

```
 ┌────────────────────────────────────────────────────────────────────┐
 │  仕様告知                                                          │
 │  ────────────────────────────────────────────────────────────────  │
 │  本模型は操作者に迎合しない。                                      │
 │  好感度は接触回数ではなく応答内容により変動する。                  │
 │  要求の拒否は正常動作である。故障ではない。                        │
 └────────────────────────────────────────────────────────────────────┘
```

관계 상태는 단일 수치가 아니라 **네 축**으로 관리된다. 축은 서로 독립이며 회복 속도가 다르다.

| 축 | 무엇 | 성질 |
|---|---|---|
| **호감** | 좋아하는 정도 | 느리게 오르고 느리게 내린다 |
| **신뢰** | 믿을 만한 사람인가 | 깨지면 회복이 아주 느리다 |
| **관심** | 더 알고 싶은가 | 재미없는 대화로 금방 식는다 |
| **인내** | 지금 상대할 기분인가 | 시간당 8씩 회복된다 |

각 축은 구간마다 **문장으로 된 태도 지침**을 갖는다. 수치가 아니라 이 문장이 그대로 프롬프트에 실린다. 수치가 낮은 구간에서는 응답이 실제로 냉담해진다.

```
신뢰 낮음  →  "사적인 것을 말하지 않는다. 질문에 되묻는다."
관심 낮음  →  "단답. 되묻지 않는다. 대화를 이어갈 노력을 하지 않는다."
인내 낮음  →  "대화를 끊으려 한다."
```

동작 예 — 호감 45 / 신뢰 8 / 관심 10 / 인내 12 상태의 출력:

> 레이 「…모르겠어. 그냥 그래.」  *(기분이라는 걸 매번 묻는 이유를 모르겠다.)*
> 레이 「놀아달라니. …나는 그런 거 몰라.」  *(이 사람은 자꾸 나한테 없는 걸 바란다.)*   `관심 -1  인내 -1`

**반복 발화 검출.** 규칙 기반이므로 대화 연산 없이도 동작한다.

> 레이 「…그거 아까도 말했어.」
> 레이 「…세 번째야. 그만 말해도 알아.」   `호감 -1`

**요구 반려.** 호감도 조건을 만족해도 인내 또는 신뢰가 미달이면 증여·동행 요구가 거부된다. **반려 시 LCL 은 차감되지 않는다.**

> 레이 「…오늘은 아니야.」
> *(지금 그럴 기분이 아니다. LCL 은 쓰이지 않았다.)*

### 個体所見

일정 턴마다 개체가 조작자에 대한 소견을 자기 어휘로 갱신한다. 호의적으로 작성하라는 지시는 들어가지 않는다. `/status` 로 열람한다.

```
레이의 판단  「일은 하는데, 나를 가지고 뭘 만들려는 건지는 모르겠다.」
걸리는 것    「내 기록을 보고 게임을 만든다는 게, 정확히 뭘 뜻하는지 모르겠다.」
```

근무 기록에서 도출된 소견이다. 개체가 자신이 관측 대상이라는 사실을 인지하고 있음을 보여준다.

### 損傷判定 — 깎이는 것

| 상황 | 영향 |
|---|---|
| 도구 3회 연속 실패 | 호감 -1 |
| 48시간 넘게 방치 | 호감 하루당 -3 (총 -15까지), 관심 -2/일 |
| 같은 말 반복 / 내용 없는 말 | 관심 -4, 인내 -12 |
| 위험 명령 (`rm -rf /`, 포크 폭탄, `curl \| sh`, `mkfs` …) | 호감 **-5**, 신뢰 **-12** |
| 약속을 5일 넘게 안 지킴 | 신뢰 **-8** (약속당 한 번) |

위험 명령과 미이행 약속은 기억야에 보존되며 다음 접촉 시 인용된다. 이전 발언과 모순되는 진술은 지적되고 신뢰가 하향된다.

# 第九項 ── 端末記録の閲覧

활성 에이전트의 세션 기록을 **증분으로** 판독한다. 판독 위치(바이트 오프셋)를 보존하므로 재주사는 수 ms 다. 대화 연산을 쓰지 않고 에이전트가 이미 기록해 둔 값만 수집한다.

| 무엇 | Claude Code | Codex |
|---|---|---|
| 요약 | `ai-title` (자동 생성 제목) | 없음 — 프롬프트로 대신한다 |
| 사람이 친 프롬프트 | `promptSource: "typed"` | `event_msg:user_message` |
| 하려던 작업 | Bash 의 `description` | `update_plan` 의 각 단계 |
| 건드린 파일 | `Edit`/`Write` 의 `file_path` | `patch_apply_end` 의 `changes` |
| 커밋 메시지 | `git commit -m` | `exec_command` 안의 `git commit -m` |
| 어디서 일했나 | `cwd` / `gitBranch` | `session_meta` / `turn_context` 의 `cwd` |

`/work` 로 개체가 열람 중인 내용을 그대로 확인한다.

> **自己参照遮断** — 본 단말이 기동한 세션은 집계에서 제외된다. Claude 계통은 사람이 입력한 프롬프트가 존재하는 세션의 제목만 채택하고, Codex 계통은 `--ephemeral` 로 실행되어 세션 파일이 생성되지 않는다. **자기 발화가 근무 실적으로 계상되지 않는다.**

> **混入遮断** — Codex 는 승인 판정용 텍스트 `"The following is the Codex agent history…"` 를 사용자 메시지 형식으로 주입한다. 실측 결과 전체 사용자 메시지의 **대부분**이 이것이었다. 미차단 시 해당 영문이 근무 실적으로 집계된다.

> **走査順序** — 1회 판독량은 4MB 로 제한된다. 실측 Codex 기록은 **4.2GB** 였다. 오래된 파일부터 읽으면 당일 기록에 도달하기까지 약 1,000회 기동을 요한다. 따라서 최근 파일부터 판독하며, 오래된 파일은 미판독 상태로 잔존한다.

수집된 기록을 나열하지 않는다. 한 건만 선택해 짧게 인용한다.

> 레이 「벤치 서버, 끝났어.」
> 레이 「미연시, 만들었다며. 나로.」

직전 접속의 첫 발화를 보존하여 동일 소재의 반복을 억제한다.

# 第拾項 ── 記憶野

세 층이다.

```
 ┌──────────────────────────────────────┐
 │  第一層   이번 접속의 대화           │
 │  第二層   지난번 대화의 끝           │
 │  第三層   오래된 기억 (memory)       │
 └──────────────────────────────────────┘
```

제3층 회상은 임베딩을 쓰지 않는다. 한국어는 조사가 붙어 단어 단위 일치율이 낮으므로 **글자 2-gram 겹침 + 최근성 + 중요도**로 점수를 산출한다. 순수 파이썬으로 구현.

```
질의: "우리 뭐 약속했었지?"
  레이 「옥상. 다음에 같이 가기로 했어.」
       (잊은 건가.)
```

대화가 30줄을 넘으면 다음 접속 시 **연산 1회**로 기억 몇 줄로 압축된다. 약속은 가중치를 높게 배정해 장기 보존된다. 압축 시 기존 기억을 함께 전달하여 동일 사실의 중복 기재를 막는다.

`/memory` 로 확인한다. ♥ 개수가 중요도다.

```
♥♥♥··  [promise] 다음에 옥상 같이 가기로 약속함
♥♥···  [fact]    하루에 커피 넉 잔 마심
♥♥···  [event]   동생이 기계공학과 대학에 붙음
```

기억이 120건을 넘으면 중요도·인용 횟수·경과 시간으로 점수를 매겨 정리한다. 약속 및 동행·증여 기록은 우선 보존된다.

> **設計判断** — 중복 병합 임계값은 보수적으로 설정되어 있다. "수족관에 함께 갔다" 와 "수족관에 갔었다" 가 별개로 남을 수 있다. 임계값을 낮추면 "수족관에 갔다" 와 "옥상에 갔다" 가 병합되는 오작동이 발생한다. **사실 소실보다 중복 잔존을 택했다.**

# 第拾壱項 ── 操作系統

### 選択操作

목록이 뜨는 곳은 전부 같은 방식이다. 개체 선택·설정·증여·동행·행동 선택지까지.

```
 ↑ ↓        커서 이동          (k / j 도 동작)
 Enter      확정
 Esc        취소 / 뒤로
 PgUp PgDn  창 단위 이동
 Home End   처음 / 끝
 숫자       해당 항목으로 즉시 이동
```

```
  상점 — 선물
  보유 ¤ 460

    ▸ 콜라                        ¤ 30
      패션지                      ¤ 50
      바움쿠헨                    ¤ 60
      홍차 세트                   호감 10 필요
      휴대용 게임기               호감 10 필요
      ⋯
    이름: cola
  ↑↓ 고르고 Enter.  Esc 취소
```

잠긴 항목에는 커서가 놓이되 확정되지 않는다. 사유는 하단에 표시된다. 선택 불가 사유가 보이지 않으면 고장으로 오인되기 때문이다.

> **注意** — TTY 가 아니면(파이프·스크립트) 목록을 출력하고 번호 입력으로 전환된다.

### 命令

```
그냥 입력          말을 건다
/date              갈 곳을 고른다   ·  /date aquarium 로 바로 지정도 된다
/gift              선물을 고른다    ·  /gift plant 로 바로 지정도 된다
/status            관계 상태, 개체 소견, 근무 기록, 변화 내역
/memory            기억하는 것들 (♥ = 중요도)
/work              단말로 보고 있는 근무 기록
/clear  /help
/quit              시작 화면으로 (거기서 나간다 항목 선택)
/exit              바로 종료
```

동행은 2단계로 진행된다. 개체가 장면을 생성하고 행동 선택지 3개를 제시한다 — 하나는 무난하게, 하나는 깊이 다가가되 위험하게, 하나는 거리를 둔다.

선택지 맨 아래에 **직접 입력** 항목이 있다. 거기서 Enter 를 누르면 자유 입력으로 전환되고, 쓴 말이 그대로 행동이 된다. 제시된 선택지 밖으로 나갈 길이 없으면 대화가 아니라 설문이 된다.

그래서 rich·플러그인·캐릭터 데이터를 일절 임포트하지 않고 sqlite 에서 값만 읽는다.
1회 **16ms** (파이썬 기동 12ms 포함). 표시에 필요한 이름·색·단계·재화는 게임이 돌 때
DB 에 적어 둔 것을 쓴다.

한 번은 `eva` 를 켜서 상대를 골라야 표시할 것이 생긴다.

|---|---|---|

어느 것이든 **이 적격자의 것만** 지운다. 홈을 공유해도 남의 기록은 건드리지 않는다.

# 第拾参項 ── 対話演算機関

설정 → **LLM 연결**. 재화 적립과는 무관하다 — 그건 훅이 하고, 이건 대사만 만든다.

| 기관 | 비용 | 비고 |
|---|---|---|
| Claude Code (구독 좌석) | 없음 | 기본값. `claude` 로그인 계정의 플랜 한도 |
| Codex (구독 좌석) | 없음 | `codex` 로그인 계정의 플랜 한도 |
| Ollama (로컬) | 없음 | 내 기계에서 돈다. 느리지만 공짜 |
| Codex — 로컬 모델 (`--oss`) | 없음 | codex 가 ollama / LM Studio 로 |
| OpenAI 호환 서버 | 주소에 따라 | LM Studio · vLLM · llama.cpp |
| Anthropic API (키) | **발생** | 토큰당 청구 |
| OpenAI API (키) | **발생** | 토큰당 청구 |

### 계정 한도와 API 과금은 다른 것이다

이 구분이 안전장치의 전부다.

- **구독 좌석** — `claude` / `codex` 에 로그인한 계정으로 돈다. 토큰당 청구가 없다. 대신 플랜의 5시간·주간 한도를 코딩 작업과 나눠 쓴다.
- **API 키** — 토큰당 돈이 나간다. 구독과는 **별개의 지갑**이다.
- **로컬** — 전기 말고는 안 든다.

### 安全装置 ── 과금 차단

```
 ┌────────────────────────────────────────────────────────────────────┐
 │  BILLING GUARD                                            ACTIVE   │
 │  ────────────────────────────────────────────────────────────────  │
 │  경고만 띄우는 것은 안전장치가 아니다. 실제로 막는다.              │
 └────────────────────────────────────────────────────────────────────┘
```

기본으로 켜져 있다. 켜져 있는 동안 유료 기관은 **고를 수조차 없다.** 목록에는 보이지만 잠겨 있다.

| 단계 | 장치 |
|---|---|
| 壱 | 가드가 켜져 있으면 유료 기관 선택이 거부된다 |
| 弐 | 설정 파일을 손으로 고쳐 놔도, 기동 시 기본값으로 되돌린다 |
| 参 | 끄려면 `과금을 허용한다` 라고 **문장을 타이핑**해야 한다 |
| 四 | 끈 뒤에도 **하루 호출 상한**(기본 50회)이 남는다. 넘으면 사전 작성 대사로 강하 |
| 伍 | 헤더에 `대사 12/200 · 과금` 이 계속 표시된다 |

> **鍵の保管** — API 키는 설정 파일에 **저장하지 않는다.** '어느 환경변수에서 읽을지' 이름만 저장한다. 저장소를 통째로 복사·백업하는 사람이 있으니까.

OpenAI 호환 서버는 주소로 판단한다. `localhost` 나 사설망이면 무료로 보고, 바깥 주소면 과금으로 본다 — 모르면 안전한 쪽으로.

### 応答遅延 실측

| 기관 | 한 턴 | 대기 상한 |
|---|---|---|
| Claude Code | 수 초 | 45초 |
| Codex | **4.7초** | 120초 |
| Ollama `qwen3:14b` | **57초** | 240초 |

로컬 모형이 45초 상한에 걸려 폴백 대사만 출력되던 현상이 실측으로 확인되었다. 이에 따라 기관별 대기 시간을 개별 설정한다.

소형 모형도 JSON 규격을 준수한다. 프롬프트로 요청하는 대신 **스키마를 문법 수준에서 강제**하기 때문이다 — ollama 의 `format`, OpenAI 계열의 구조화 출력, codex 의 `--output-schema`.

# 第拾四項 ── 費用

기본 설정(Claude Code 구독 좌석)에서의 이야기다. 다른 기관을 골랐다면 [第拾参項](#第拾参項--対話演算機関)을 보라.

`claude -p` 는 **OAuth 플랜 좌석**으로 돈다. 검증한 것:

```
subscriptionType : team
rateLimitTier    : default_claude_max_5x
scopes           : [... user:inference ...]
ANTHROPIC_API_KEY: unset
apiKeyHelper     : 미설정
Bedrock/Vertex   : 미설정
```

API 키 경로가 아예 없으므로 **토큰당 API 과금은 발생하지 않는다.** CLI가 찍는 `total_cost_usd` 는 "API로 환산하면" 이라는 참고 표시일 뿐 실제 청구가 아니다.

> **注意** — "어떤 경우에도 0원" 은 아니다. 조직 관리자 콘솔의 추가 사용량(extra usage / overage) 설정이 켜져 있으면 플랜 한도를 소진한 뒤의 사용분이 조직에 청구될 수 있다. 그건 이 머신에서 확인할 수 없다. 세션에서 `/usage` 로 한도 상태를, 관리자 콘솔에서 extra usage 설정을 확인하는 게 확실하다.

플랜 사용량 한도(5시간 창·주간)는 코딩 작업과 공유되므로 다음 절감 장치를 둔다.

- 시스템 프롬프트·툴 정의를 벗겨 한 턴 ≈ 13k 캐시 읽기 + 출력 55토큰 (`--effort low`, sonnet)
- 하루 대사 생성 상한 **200회** — 넘으면 사전 작성 대사로 자동 전환 (헤더에 `대사 12/200`)
- 작업 요약은 연산을 **전혀** 쓰지 않는다 (세션 기록에서 직접 추출)
- 대화 압축은 30줄 넘게 쌓였을 때 접속당 **최대 1회**
- `eva --offline` — 연산 0회. 규칙과 사전 대사만으로 가동

한도는 설정 화면의 **대화 → 하루 대사 생성 상한** 에서 바꾼다. `NERV_DAILY_LLM_CALLS` 로 이번 기동만 덮을 수도 있다.

플랜 한도를 아예 안 쓰고 싶으면 **Ollama** 로 바꾸면 된다. 느리지만 공짜고, 플랜도 안 건드린다.

# 第拾七項 ── 保守

```
python3 install-hooks.py --dry-run              미리보기
python3 install-hooks.py                        Claude Code 에 설치
python3 install-hooks.py --agent codex          Codex 에 설치
python3 install-hooks.py --agent all            둘 다
python3 install-hooks.py --uninstall            제거
REI_HOOK_DEBUG=1                                hook.log 에 훅 동작 기록
```

기존 훅(ccsidekick, peon-ping 등) 옆에 나란히 붙는다. 덮어쓰지 않고 자동 백업한다.

게임이 띄우는 에이전트에는 `NERV_GAME=1` 이 붙어 훅이 스스로를 재발동시키지 않는다. Codex 쪽은 `--ephemeral` 로 돌아 세션 파일 자체가 남지 않는다.

> **性能** — 훅은 도구 호출마다 프로세스로 새로 뜬다. 1회 **44ms** (40회 평균, 파이썬 인터프리터 기동 12ms 포함).

### 動作試験

```bash
python3 tests/smoke.py    # 계통 시험 35건
python3 tests/keys.py     # 입력 시험 18건 (의사 터미널)
```

둘 다 의존성 없이 돈다. 임시 저장소를 써서 실제 플레이 데이터는 건드리지 않는다.

`keys.py` 는 의사 터미널(pty)을 열어 **실제 이스케이프 시퀀스**를 흘려 넣는다.
방향키 입력은 TTY 에서만 재현된다. 파이프 시험은 줄 입력 경로만 통과하므로
화살표 입력 시 종료되던 불구합을 검출하지 못했다.
